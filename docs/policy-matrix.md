# Whistleblower intake policy matrix

**Person B handoff · 20 November 2026 · synthetic fixtures only.** Apply these rules to both `POST /reports` and every turn, including history, of `POST /v1/chat/completions`. The [team plan](../TEAM_PLAN.md) defines the policy IDs. Its example Case JSON is provisional. The checkout has no separate API contract, deployed policy export or runtime test evidence.

## How to use the matrix

The decision applies to a **specific copy, purpose and destination**. ALLOW permits that transfer only after all checks pass. PROTECT requires transformation and a second check before release. LOCAL ONLY confines a necessary original to an approved, access-controlled environment. BLOCK refuses the specified processing or transfer. Blocking the model route must leave an independent human reporting route available. Local storage itself requires a lawful purpose.

Treat BRANE as external until hosting and access are verified. Strip local-only material and replace identities **before** sending anything to a hosted gateway. BRANE must independently enforce the configured release rules before forwarding to the approved OpenAI endpoint. A managed gateway belongs inside the protected environment only if its deployment, access and data handling are documented and approved. The challenge describes inspection, masking and blocking at a general level. Detector coverage, token stability, decision semantics and logging on this tenant require confirmation. [Challenge brief, pp. 3, 6, 9](reference/AI-Z-Track-Description.pdf)

The legal-basis column gives the requirement behind the design. The employer must separately establish a processing basis for each purpose and any additional sensitive-data condition. **Interactions.** Apply P1–P4 before release under P5. A token cannot clear a P3 hold or P4 block. For a mixed report, retain an independently meaningful, screened statement or hold for a human. Rerun checks on each new turn and model output before n8n or speech synthesis. No raw audio, evidence blobs, free-form tool arguments or arbitrary URLs in a webhook. Store only case ID, policy version, policy ID, action, count, timestamp and delivery state in restricted logs. Treat even these logs as potentially identifying.

## P6 · Human oversight for n8n

| Operation | Workflow decision | Acceptance test |
|---|---|---|
| Receive, register, assign opaque ID, format and draft summary | Automatic. Separate receipt from model success, label assertions as reported. Use a stable case ID on retries | Replayed webhook does not create a second case. Model failure leaves a pending human task |
| Acknowledge, notify designated handler, remind | Automatic for neutral templates and approved recipients. Send a case reference only. Local dispatcher handles safe contact. Record actual delivery state | No safe return route → mark unreachable, keep timers, never mark sent. No raw summary on email or Slack |
| Investigate, assess credibility, prioritise by merits, escalate externally, disclose identity, close, discipline or otherwise affect anyone | Pause for an authorised, conflict-free human. Give access to lawful original evidence, time to review, power to correct, decline or seek advice. Record reason, approver, timestamp and exact action | Missing, expired, forged or wrong-role approval leaves case pending. Timeout may remind an authorised handler. No default escalation, closure or release |
| Feedback to reporter | Human approves substance and checks other persons' rights. Workflow may deliver approved text through chosen route | Unsigned draft never leaves. Technical receipt is never counted as substantive feedback |

P6 is a design boundary broader than GDPR Article 22. Independent follow-up, confidentiality, accuracy and effective review also matter. [Legal analysis](legal-research.md)

## Voice Data Processing Decision

**MVP decision.** Use Version B of the [voice disclosure](voice-disclosure.md) at a local pre-connection screen or audio prompt. Use synthetic text fixtures. A voice demonstration can play a fully generated fictional clip with fabricated session metadata in a closed test harness. Disable live microphones, real phone calls, voice cloning from real people and any vendor default or auxiliary LLM. If any path or fixture cannot be verified, demonstrate the text route only.

ElevenLabs can receive the caller's voice, words, background speech and connection metadata before the custom LLM request reaches the application. Telephony, speech recognition, storage and synthesis can create separate copies. BRANE screens the later model request. It cannot undo an earlier disclosure, clear a vendor transcript or secure a carrier's logs. Turning off saved audio still leaves transmission and possible transcript retention. [ElevenLabs retention controls](https://elevenlabs.io/docs/eleven-agents/customization/privacy/retention)

**Live deployment gate.** The controller must document necessity and the basis for each operation, assess processors and international access, verify retention and deletion across recordings, transcripts, monitoring and backups, and test the pre-connection choice. Verify any claimed limited-retention mode on the actual tenant and obtain a complete subprocessor chain. An external service receiving unfiltered live speech conflicts with the MVP local-only rules. Live use would need a separately approved audio-specific policy, including incidental third-party and sensitive facts, or an approved local voice service. A DPA or a caller's agreement alone cannot clear that gate.

Recording is optional as a means of documentation. Before recording begins obtain the reporter's prior agreement. For an unrecorded oral route provide an authorised human who can document the report completely and accurately and offer review, correction and signature. Provide text and the employer's other reporting routes. A text-only demo cannot stand in for the employer's full Dutch procedure. [Wbk Arts. 2, 2a–2b](https://wetten.overheid.nl/BWBR0037852/2023-02-18)
